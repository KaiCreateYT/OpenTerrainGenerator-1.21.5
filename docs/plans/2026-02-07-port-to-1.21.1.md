# OTG Port from MC 1.20.1 to MC 1.21.1 — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Port OpenTerrainGenerator mod from Minecraft 1.20.1 to 1.21.1 (Fabric platform only).

**Architecture:** Between 1.20.1 and 1.21.1 there are 6 intermediate MC versions with breaking changes. The hardest changes are: Java 17→21, `ResourceLocation` constructor privatized, `Codec`→`MapCodec` for generators/biome sources, `Executor` removed from chunk gen methods, `RegistryDataLoader` internal restructure (local capture mixin breaks), and `ReloadableServerResources.updateRegistryTags()` signature change. Most common module code is untouched — changes are concentrated in `platforms/fabric/`.

**Tech Stack:** Fabric Loader, Fabric API 0.116.7+1.21.1, Architectury 13.0.8, Cardinal Components 6.1.3, Java 21, Loom 1.7+

**Testing:** No automated tests exist. Each task must be verified by compiling (`./gradlew build`). Final verification is manual in-game testing.

## Task 7: Rewrite `RegistryLoaderMixin` (HARDEST TASK)

**Context:** This is the most critical and complex mixin. In 1.21.1:
- The private `load()` method's local variables changed from `List<Pair<WritableRegistry<?>, Object>>` to `List<RegistryDataLoader.Loader<?>>`.
- `RegistryDataLoader.Loader` is a **private** inner record, so it can't be directly referenced in mixin parameters.
- The `Pair`-based helper methods (`getRegistry()`, `getRegistryOrThrow()`) all break.

**Files:**
- Modify: `platforms/fabric/.../mixin/RegistryLoaderMixin.java`
- Potentially create: `platforms/fabric/.../mixin/RegistryDataLoaderLoaderAccessor.java` (accessor for private `Loader` record)

### Strategy Options

**Option A: Target the private overload with `@Local` (recommended)**

Instead of targeting the public `load(ResourceManager, RegistryAccess, List<RegistryData<?>>)`, target the private `load(LoadingFunction, RegistryAccess, List<RegistryData<?>>)` which has the actual local variables. Use MixinExtras `@Local` annotation to capture locals without `CAPTURE_FAILHARD`.

```java
@Inject(
    method = "load(Lnet/minecraft/resources/RegistryDataLoader$LoadingFunction;" +
             "Lnet/minecraft/core/RegistryAccess;" +
             "Ljava/util/List;)Lnet/minecraft/core/RegistryAccess$Frozen;",
    at = @At(
        value = "INVOKE",
        target = "Ljava/util/List;forEach(Ljava/util/function/Consumer;)V",
        ordinal = 1
    )
)
private static void loadOTGPresets(
    @Coerce Object loadingFunction,
    RegistryAccess registryAccess,
    List<RegistryDataLoader.RegistryData<?>> list,
    CallbackInfoReturnable<RegistryAccess.Frozen> ci,
    @Local(ordinal = 1) List<?> loaders
) {
```

**Option B: Create an accessor for `Loader.registry()`**

Since `Loader` is private, create an accessor interface:
```java
@Mixin(targets = "net.minecraft.resources.RegistryDataLoader$Loader")
public interface RegistryDataLoaderLoaderAccessor {
    @Accessor("registry")
    WritableRegistry<?> getRegistry();
}
```

**Option C: Use reflection**

Access `Loader.registry()` via reflection. Less clean but simpler.

### Implementation Steps

**Step 1: Add MixinExtras dependency if not present**

MixinExtras is bundled with Fabric Loader 0.15+, so `@Local` and `@Coerce` should be available. Verify.

**Step 2: Create accessor for `RegistryDataLoader.Loader`**

Create `RegistryDataLoaderLoaderAccessor.java`:
```java
@Mixin(targets = "net.minecraft.resources.RegistryDataLoader$Loader")
public interface RegistryDataLoaderLoaderAccessor {
    @Accessor("registry")
    WritableRegistry<?> getRegistry();
}
```

Register it in `otg-fabric.mixins.json`.

**Step 3: Rewrite injection signature**

Change from `LocalCapture.CAPTURE_FAILHARD` with `Pair` parameters to `@Local` annotation. The crucial change:
- OLD: `List<Pair<WritableRegistry<?>, Object>> registries` (local capture)
- NEW: `@Local List<?> loaders` (MixinExtras @Local)

**Step 4: Rewrite helper methods**

Replace all `Pair<WritableRegistry<?>, Object>` parameter types with `List<?>` and use the accessor to extract registries:

```java
// OLD:
private static <T> WritableRegistry<T> getRegistry(List<Pair<WritableRegistry<?>, Object>> registries, ResourceKey<Registry<T>> key) {
    return registries.stream().map(Pair::getFirst).filter(r -> r.key().equals(key)).findFirst().orElse(null);
}

// NEW:
@SuppressWarnings("unchecked")
private static <T> WritableRegistry<T> getRegistry(List<?> loaders, ResourceKey<Registry<T>> key) {
    for (Object loader : loaders) {
        WritableRegistry<?> registry = ((RegistryDataLoaderLoaderAccessor) loader).getRegistry();
        if (registry.key().equals(key)) {
            return (WritableRegistry<T>) registry;
        }
    }
    return null;
}
```

**Step 5: Update all method signatures that take the registries list**

Every method that takes `List<Pair<WritableRegistry<?>, Object>>` must change to `List<?>`:
- `loadOTGPresets()` — injection handler
- `registerBiomes()`
- `createLevelStems()`
- `registerNoiseGenSettings()`
- `registerDimensionTypes()`
- `printAllRegistriesForDebug()`
- `getRegistry()`
- `getRegistryOrThrow()`

**Step 6: Remove `Pair` import**

Remove `import com.mojang.datafixers.util.Pair;`

**Step 7: Also update all `new ResourceLocation(...)` in this file**

9 occurrences (already covered in Task 2 but execute here if not already done).

**Step 8: Compile test**

Run: `./gradlew build`
Focus on mixin application errors. If `@Local` capture fails, adjust ordinal or use different capture strategy.
